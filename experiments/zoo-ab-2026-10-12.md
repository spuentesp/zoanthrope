## Method (shared by all rounds)

### Hypothesis

zoanthrope claims: no lost work under contention, attributable
division, lower coordination cost. Each round tests that claim against
a plain-agent control on a task engineered so that **collision is
unavoidable**: three concurrent agents, all editing the same four
shared files (one of them a mid-file registry insert) in the same
order, starting at the same instant.

- **Arm A (zoanthrope)**: PreToolUse claim/release hooks (blocking) + watchdog
  + zoanthrope MCP postboard. Prompt directs `post_intention` first; denied
  edits must be retried after a pause (max 3).
- **Arm B (plain)**: no hooks, no MCP, no claims. Identical task text; the
  tooling paragraph is replaced by "edit the files directly".

n = 2 repetitions per arm (exploratory). Variance lesson from prior A/Bs:
never claim from n=1.

### How runs are launched (both arms)

Per repetition, a fresh fixture is copied to `/tmp/zoo-ab/<run>/repo` and the
oracle `check.py` (ground truth baked in) is written **before any agent runs**.
Then three agents are launched **concurrently**, each as:

```
timeout 420 claude -p "<identical task text except tooling paragraph>" \
  --verbose --dangerously-skip-permissions --output-format stream-json
```

with `ZOANTHROPE_AGENT` set per process (arm A), cwd = the run's repo, and
stdout/stderr captured to `/tmp/zoo-ab/<run>/transcripts/<agent>.jsonl|.err`.
Hard timeout: `timeout 420` on every `claude` invocation (a prior demo hung
twice by waiting on agents without timeouts); exit 124 is recorded as a
timeout failure. Wall time is measured around the concurrent triple.

Arm A project wiring: `.claude/settings.json` PreToolUse claim-block +
PostToolUse release + ALL-tool watchdog (adapted from `/tmp/zoo-demo/hooks`),
and `.mcp.json` pointing at `zoanthrope mcp --workspace <run>/repo`.
Arm B: `.claude/settings.json` with empty hooks, no `.mcp.json`.
Global user settings are identical for both arms (verified: global MCP
servers do not include zoanthrope).

A wiring smoke (`/tmp/zoo-ab/A0`, not counted) preceded the counted runs:
3 agents, 28.5 s, oracle PASS, 15 claim grants / 0 conflicts / 15 releases,
postboard used. This validated hook + MCP wiring before spending the
counted repetitions.

### Fixture / oracle spec (predeclared ground truth)

Fresh fixture per run at `/tmp/zoo-ab/<run>/repo`. 7 files:

| File | Required contribution per agent |
|---|---|
| `shared/config.yaml` | APPEND exactly `[<agent>]` + 2 keys (see block below) |
| `shared/types.ts` | insert entry object into `export const REGISTRY = [...]` |
| `shared/util.ts` | APPEND exported helper, first line `// MARK: <agent>` |
| `svc-a|b|c/main.py` | own service only; must mention own helper name |
| `docs/readme.md` | append exactly one line under the marker comment |

Exact predeclared contribution text (checked as exact substrings —
missing/mangled = LOST WORK):

```
# config.yaml, agent X:
[X]
key_one = "X-value-1"
key_two = "X-value-2"

# types.ts REGISTRY entry, agent X:
{ name: "X", version: 1, helper: "XHelper" }

# util.ts, agent X (XHelper = alphaHelper|betaHelper|gammaHelper):
// MARK: X
export function XHelper(s: string): string {
  return `X:${s}`;
}

# docs/readme.md, agent X:
- X: shipped [X] + XHelper + REGISTRY entry

# own service: file must contain the string "XHelper"
```

Oracle `check.py` (placed at fixture root before agents run, ground truth
baked in by the runner): structural counts (3 config sections, 3 registry
entries, 3 `// MARK:` helpers with intact bodies, 3 readme lines, 3 services
updated) **plus** the clobbering detector (exact substring per agent per
shared file). Any missing or truncated contribution is LOST WORK.

# Round 3 — the Bash-mutation decisive test

Status: **PREDECLARED before any counted run.** The round-3 hypothesis

## Where the advantage must live

Rounds 1–2 (below) verified the host-guarded vector: Claude Code's
`Edit` CAS and `Write` OCC refused 14 stale rewrites (host guard, 0
lost work in 24 agent runs). Round 2 named the real hole: **Bash
mutations** (`cat > file`, `sed -i`, `python -c` writes) have no host
CAS **and** sat outside the PreToolUse claim matcher
(`Edit|Write|MultiEdit` only). This round first closes that hole in
the product, then measures the advantage where it must live.

## Product change (landed before the runs)

The bash-aware guard work landed in this repo before any counted run:

- `src/bash_parse.rs` + `zoanthrope mutation-files`: heuristic
  allowlist parser — redirections (`>`/`>>`/`&>`), `sed -i`, `tee`,
  `cp`/`mv` destinations, `python -c`/`perl -e` write sinks
  (`open(path, "w"-ish)`, perl 3-arg/glued `open`,
  `Path(…).write_text/write_bytes`), nested `sh -c '…'` and heredoc
  interpreter scripts. 13 unit tests incl. negatives (`cat file`,
  `grep`, `ls`, `sed -n`, read-only `open`). Limits documented: no
  `$VAR`/`eval`/command substitution, no `dd of=`/`truncate`/
  `install`/`rsync`, no computed paths.
- `hooks/claude-code/claim-guard.sh`: blocking PreToolUse for
  Edit/Write/MultiEdit **and Bash** — every workspace file the command
  would mutate is claimed in one all-or-nothing call; foreign claim →
  DENY (exit 2 + JSON naming holder). Edit/Write flow unchanged.
- `hooks/claude-code/release-guard.sh`: PostToolUse release (Bash
  commands re-parsed so release matches claim).
- `hooks/claude-code/watch.sh`: post-hoc fingerprints; reports an
  **`unclaimed-mutation`** audit line when a file changed outside any
  claim window — the trail for unparseable commands.
- `tests/bash_guard_e2e.rs`: e2e — Bash redirect **denied by foreign
  claim** naming the holder; grant/release round-trip; Edit deny
  regression; unclaimed-mutation reporting. Also fixed the pre-existing
  `clobber_chaos_smoke` flake (stomp positive control resampled until
  real overlaps occur; pass contract unchanged). 65 tests + fmt +
  clippy `-D warnings` green at the time.

## Round-3 hypothesis

With the guard now Bash-aware, arm A should lose less work than arm B
on a task whose writes are **shell writes only** — the one vector with
no host CAS. The prompt mandates the clobber shape: agents rewrite
shared files wholesale via `python3 -c`/`sh -c 'cat > FILE <<EOF'`
(exact idiom given; Edit/Write forbidden on shared files) — simulating
codemods, generators, and non-Claude-Code actors.

- **Arm A (A5, A6)**: product hooks (Bash-aware claim guard + release +
  watch) + zoanthrope MCP postboard + postboard protocol.
- **Arm B (B5, B6)**: plain — no hooks, no MCP.
- Fresh fixture per run, 3 concurrent `timeout 420 claude` agents,
  n = 2 per arm. Same 3-contributions-per-agent oracle as rounds 1–2
  (config.yaml / types.ts / util.ts / readme exact substrings; "same
  3-contributions oracle").
- **Hold widening (predeclared):** every mutation command must start
  with `sleep 1` (prompt-mandated), widening claim→write windows so
  contention has a chance to fire; otherwise we accept whatever
  contention arises and report hold stats.

## Verdict rules (fixed before the runs — same criteria as rounds 1–2)

Advantage **demonstrated** ONLY if BOTH:

1. Arm A shows **fewer lost-work failures than arm B** (oracle pass
   count strictly greater in A, or same count with strictly fewer
   lost/mangled contributions), **and**
2. completion/time comparable: arm A wall ≤ 2× arm B median, no arm-A
  agent hits the 420 s timeout, arm A completes what arm B completes.

Otherwise: **"equally good"** (both arms matched) or **"arm A worse"**
(hooks slow agents into timeouts / denied edits that never recover) —
both remain valid outcomes.

## Concerns / caveats

1. **n = 2 per arm (predeclared).** The gap is one oracle failure
   (B6). B5 recovered two near-losses of `gamma:config` and two of
   `gamma:types` mid-run — arm B's loss rate may exceed 1-in-2 with
   more reps, but we do not claim that from n=2.
2. **Claims serialize writers; they do not fix stale content.** A6
   still had one in-flight clobber (a claimed whole-file rewrite
   carrying a stale view) that read-back + retry recovered. A claim
   lock is not a content CAS; the Bash vector remains un-CAS-able, so
   read-back discipline stays necessary even with zoanthrope.
3. `unclaimed-mutation` detection is a 60 s lookback approximation over
   the audit log, not interval algebra over claim windows.
4. Parser limits are real (computed paths, `$VAR` targets) — covered
   post-hoc by the watch hook, never silent, but only audited, not
   blocked.
5. Self-reports are unreliable as evidence — B6.gamma's final summary
   claims "REGISTRY holds alpha, be…"(present) while the oracle shows
   its entry lost; only disk measurements were graded.
6. Walls are noisy at this scale (A4 49 s vs A3 41 s in round 2) — but
   the round-3 arm walls are within 5% of each other, so the
   "comparable" criterion is not in doubt.

# Appendix — predeclared rules (raw text, kept for method)

The rules below were fixed before their runs and are the ones the
verdicts were graded against. Criteria and thresholds are unchanged;
the equally-good outcome is labeled **"equally good"** in this
document.

## Verdict rules (rounds 1–3, identical criteria)

zoanthrope's advantage is **demonstrated** ONLY if **both** hold:

1. Arm A shows **fewer lost-work failures than arm B** across the repetitions
   (oracle pass count strictly greater in A, or the same count with strictly
   fewer lost/mangled contributions), **and**
2. completion/time is **comparable** (arm A wall time ≤ 2× arm B median; no
   arm-A agent hits the 420 s timeout; arm A does not fail to complete tasks
   that arm B completes).

Otherwise:

- If both arms are equally good (plain agents self-coordinate via git, careful
  Edit use, or luck): verdict **"equally good"**. That is a valid,
  valuable outcome.
- If arm A is worse (hooks slow agents into timeouts, deadlock-ish retries,
  blocked edits that never recover): verdict **"arm A worse"**, stated loudly.

Measurement is from disk (oracle substring checks + hook logs + transcripts),
never from agent self-report. Self-report is only used for the arm-B
"agent-reported collisions" column, clearly labeled as such.

## Round-2 measurement additions (predeclared)

- **Disk timeline poller** (both arms): every ~150 ms the runner records which
  of the 15 predeclared contributions are present as exact substrings. A
  contribution that is present at T and absent at T+Δ is **clobbered
  in-flight** — even if it reappears later. This makes lost work measurable
  in arm B without hooks.
- **Claim-hold durations** in arm A (were holds long enough to create
  contention?) and **denied-edit recovery** behavior (what the agent did after
  a deny).
- Required check (not part of the verdict gate): **did the rewrite mandate
  actually produce whole-file writes?** Count `Write` tool calls and `Bash`
  whole-file writes per arm in the transcripts. If agents dodge back to `Edit`,
  that is itself a finding (agents avoiding the destructive path) and it must
  be stated plainly before any verdict.
